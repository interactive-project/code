# Neutral editors and optional integration plan

The ./editor bridge owns live driver sessions separately from persisted WorkspaceState. Drivers create a session from a host mount and readonly EditorFile projections, then implement updateFiles, setSelection, setDiagnostics and dispose. They report versioned UTF-16 text patches and typed selections. Host updates must not echo as user edits. Selection anchors/heads and diagnostic ranges are checked against current text and may not split surrogate pairs. Diagnostics are bounded to 1,000 entries with static severity and at most 256 message characters.

applyEdit dispatches through the validated domain boundary. Rejected/read-only/stale edits refresh the editor from the canonical workspace. Driver replacement prepares a new handle, refreshes current files and transfers ownership only when ready. The prior handle remains usable until transfer; superseded/late handles are disposed. Failed replacement preserves the old session. Disposal is idempotent and stale callbacks cannot edit learner data. Native driver failures produce safe static codes, with no vendor objects or messages persisted.

CodeMirror 6 is the planned initial optional browser adapter. Build it in a separate entry that imports its state/view/language modules only when the host mounts an editor. It requires a DOM-capable browser with ES modules and working contenteditable/input/composition APIs. Validate desktop Chrome/Firefox/Safari and tablet/touch devices separately, including IME composition, accessibility keyboard navigation, selection direction, undo/redo, read-only scaffolds, line endings, surrogate-pair edits and unmount cleanup. Large files, narrow layouts and low-memory devices need measured limits, not assumed support.

Monaco is an alternative optional adapter, with explicit worker/asset/CSP configuration, larger bundle/memory requirements and desktop-first support. Do not advertise touch/mobile support without testing the same patch/selection/a11y/IME suite on target devices. Monaco model URIs and worker handles remain live adapter details; map them to stable file IDs instead of persisting them. A host chooses a driver after detecting its device/capability constraints and may fall back to a plain-text adapter.

This issue implements the neutral contract and lifecycle bridge, plus representative CodeMirror/Monaco-shaped stand-ins. It does not import either editor package or claim browser/device validation. Real adapters must pass those constraints during their implementation. Node CI checks replacement, failed/delayed installation, late callback disposal, canonical file preservation, read-only rejection, selections and diagnostics; browser integration belongs to the optional adapters.
